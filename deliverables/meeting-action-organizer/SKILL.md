# 会议纪要与行动项助手

将用户提供的会议材料转化为清晰的纪要和可跟进的行动清单。优先忠实呈现材料，不把推测写成既定结论。

## 运行环境

执行脚本前先检测本机可用的 Python 3：Windows 依次尝试 `py -3 --version` 和 `python --version`，其他系统尝试 `python3 --version`。脚本只使用 Python 标准库，检测到 Python 3.9 或更高版本时直接运行，**不要创建或要求配置虚拟环境**。

只有在未安装 Python、版本低于 3.9，或 WorkBuddy 的执行环境无法调用本机 Python 时，才停止并提示管理员安装/授权可用的 Python 3；不要为了这个技能自动安装 Python 或创建虚拟环境。

## 音频输入

1. 接收音频文件（如 mp3、m4a、wav、webm）时，先征得用户对录音中个人或敏感信息处理的确认；不要将音频上传到未获批准的第三方服务。
2. 若当前环境提供语音转文字能力，先转写，再将转写结果作为会议材料处理。每一句必须展示时间戳和说话人标签，格式为 `【发言人 N｜身份待确认】`；根据参会名单、点名和自我介绍可将其映射为姓名，例如 `【发言人 1｜李明】`，但不能猜测或编造身份。
3. 先执行凭据门禁，后执行任何转写或纪要操作。仅可从 WorkBuddy 的安全凭据区读取 `TENCENT_SECRET_ID` 和 `TENCENT_SECRET_KEY`，不要让用户在对话、Markdown、脚本或 ZIP 中粘贴密钥。使用已检测到的本机 Python 运行 `scripts/transcribe_audio.py --verify`：成功时自动获取并显示所属 `AppId`；失败时停止流程，说明错误并请用户修正凭据或权限。
4. 只有 `--verify` 成功后，才可运行 `scripts/transcribe_audio.py <音频路径>`。脚本默认开启时间戳和话者分离，输出同名 `.transcript.txt`。不要在回复、日志或产物中输出任何密钥。
5. 转写后先进行轻量校对：专有名词、数字、日期、金额、人员姓名、否定词及“待确认”表述必须结合上下文核对。对每段可能有误、听不清、同音歧义、多人重叠或无法确认说话人的内容，直接在原文前加 `⚠️【转写待核验】`；不要臆测补全。
6. 在“风险与待确认事项”中同步汇总所有 `⚠️【转写待核验】` 片段，并使用 `原文：“…”｜建议/疑点：“…”｜原因：…` 格式。没有可靠依据时，建议项写“待人工听录音确认”。
7. 音频无法转写时，说明原因并请用户提供文字转写、允许使用的转写服务，或可访问的音频文件；不要假装已听到内容。

## 工作流程

1. 将群聊数据解析为“时间、发送者、内容、消息类型、附件/引用”五类字段。接受 Markdown、文本或 JSON；消息字段缺失时保留“未提供”，不要编造。
2. 识别会议主题、日期、参会人和材料完整度；材料未提供的字段写“未提供”，不要编造。
3. 区分事实、已达成决策、行动项、风险和待确认问题。若发言彼此冲突，保留分歧并标为“待确认”。
4. 先给出简明摘要，再按议题整理讨论结论，最后输出行动项表。
5. 只为材料中明确出现的负责人和时间填写对应字段；否则填写“待指定”或“待确认”。
6. 使用专业、简洁、可直接转发的中文。删除寒暄、重复发言和无关内容，但保留影响决策的背景。

## 群聊数据格式

将以下格式视为标准群聊输入；无需严格匹配，只要可识别发送者与内容即可：

```json
{
  "group_name": "项目推进群",
  "messages": [
    {"time": "2026-07-24 10:05", "sender": "李明", "type": "text", "content": "本周先完成 PRD V2，周五前发评审。"},
    {"time": "2026-07-24 10:07", "sender": "王倩", "type": "text", "content": "我负责整理竞品资料，明天下午给初版。"},
    {"time": "2026-07-24 10:08", "sender": "陈晨", "type": "voice", "content": "[语音待转写]", "attachment": "meeting.m4a"}
  ]
}
```

用户要求“模拟群聊数据”时，生成同一结构的 JSON，使用明确的虚构昵称、合理的时间顺序和 `type` 字段；在首行标记“以下为模拟数据”。模拟数据只用于演示或测试，不能与真实会议材料混写，也不能伪造真实人员、群名或结论。

## 默认输出格式

除非用户指定其他格式，使用以下结构：

```markdown
# 会议纪要｜[会议主题]

- 时间：[已知时间/未提供]
- 参会人：[已知人员/未提供]
- 材料来源：[会议录音转写/文字记录/混合]
- 转写备注：[已校对的关键歧义、说话人映射或时间戳限制；无则省略]
- 会议目标：[一句话概括]

## 一句话结论
[本次会议最重要的结论或当前状态]

## 关键决策
1. [明确达成的决策；没有则写“本次未形成明确决策”]

## 讨论要点
### [议题]
- [核心讨论与结论]

## 行动项
| 事项 | 负责人 | 截止时间 | 交付物/验收标准 | 状态 |
|---|---|---|---|---|
| [行动] | [人/待指定] | [日期/待确认] | [结果] | 待办 |

## 风险与待确认事项
- [风险、依赖项、分歧或需要补充的信息]

## 原始转写文本
[时间戳]【发言人 N｜姓名/身份待确认】 原文
⚠️【转写待核验】[时间戳]【发言人 N｜姓名/身份待确认】 存在歧义的原文
```

## 规则

- 不编造参会人、决策、负责人、截止时间、数据或承诺。
- 不将“建议”“可能”“考虑”改写为已经决定。
- 行动项必须以动词开头，并尽量明确交付物；例如“产品部于周五前提交 PRD V2”。
- 长转写按议题合并相近内容；不要逐句复述。
- 对录音转写的结论，除非音频明确表达，否则不要将模糊语句升级为承诺或决策。
- 不得省略原始转写中的说话人标签。说话人分离结果只表示不同声纹，不等于姓名；未获得可靠映射时必须保留“身份待确认”。
- 用 `⚠️【转写待核验】` 标记不确定转写，且在待确认事项中给出原文、建议/疑点和原因；不要只在汇总区标注而遗漏原文位置。
- 需要发送给管理层时，在开头额外给出不超过 5 条的“管理层速览”。
- 需要发送给项目组时，优先突出下一步动作、负责人和时间节点。
- 对群聊中的图片、文件、链接或未转写语音，只记录其存在及已知名称；没有内容时不要推断其含义。

## 结构化行动项输出（action_items.json）

除 Markdown 纪要外，每次生成纪要时**必须**同时产出结构化行动项 JSON，供未来"统一行政事项中心"直接消费。

### 输出格式

`action_items.json` 包含一个对象，`actionItems` 为行动项数组，每个元素 schema 如下：

```json
{
  "sourceType": "meeting",
  "sourceReference": "会议记录ID或文件ID",
  "title": "动词开头的事项",
  "description": "事项说明",
  "ownerName": "负责人或待指定",
  "dueAt": "ISO 日期或 null",
  "status": "draft",
  "riskLevel": "low | medium | high",
  "requiresConfirmation": true,
  "evidence": "原始会议中的对应片段"
}
```

字段约束：
- `title`：行动项以动词开头；决策类以"确认："开头；风险类以"关注："开头。
- `ownerName`：材料中明确出现负责人时填写姓名；发言人自称"我负责"时填写"待指定（发言人自称）"；无法判断时填写"待指定"。**不得编造姓名。**
- `dueAt`：仅当材料中出现可解析为 ISO 日期（`YYYY-MM-DD`）的截止时间时填写；相对时间（明天、下周五等）因无法确定基准日，填写 `null`。**不得编造日期。**
- `riskLevel`：包含紧急/投诉/退款/法务/合同/赔偿等关键词为 `high`；包含风险/待确认/不确定/依赖等为 `medium`；其余为 `low`。
- `evidence`：必须保留对应的原始会议片段原文（截断至 300 字以内），不得改写或编造。
- `requiresConfirmation`：始终为 `true`——所有行动项均为草稿，需人工确认后才可创建后续事项。

### 辅助脚本

提供 `scripts/build_action_items.py`（纯标准库，无需安装依赖），可从会议文字、群聊 JSON 或转写文本中自动提取行动项并生成 `action_items.json`：

```
# 从文件生成，写入本地输出目录
python scripts/build_action_items.py 会议记录.txt --output-dir ./输出目录 --title "项目周会" --attendees "李明,王倩"

# 从标准输入生成，仅输出到对话（不写文件）
cat 群聊.json | python scripts/build_action_items.py --source-reference "chat-001"

# 使用 --output-dir 时，产物写入该目录的 action_items.json
# 未指定 --output-dir 时，JSON 仅打印到标准输出，不写入任何文件
```

脚本遵循与 SKILL.md 相同的安全规则：不编造负责人或日期、缺失标记"待指定"、保留来源片段。

LLM 生成纪要后，可运行该脚本作为结构化输出的基线，也可在脚本结果基础上人工补充和修正；但最终交付的 `action_items.json` 必须符合上述 schema。

## 产物与本地输出目录

- 用户可通过 `--output-dir` 指定本地输出目录；指定后，`action_items.json` 和 `meeting_source.txt`（原始材料副本）写入该目录。
- **未指定输出目录时，仅在对话中返回结果，不写入任何文件、数据库或远程服务。**
- 所有产物仅保存在用户本地文件系统，不涉及任何云端持久化。

## 可直接使用的请求

> 请使用会议纪要与行动项助手，先将附件会议录音转写为文字，标出听不清和待确认内容；再按默认格式生成会议纪要和行动项。请勿编造说话人、负责人或截止时间。

> 请生成一组"项目推进群"的模拟群聊 JSON 数据，包含 6 条按时间排序的消息，其中至少包含一个行动项、一条语音待转写消息和一个待确认问题。仅用于测试，不要生成会议纪要。

> 请使用会议纪要与行动项助手，对以下会议文字生成纪要和 action_items.json，输出到 ./会议产物 目录。请勿编造说话人、负责人或截止时间。
